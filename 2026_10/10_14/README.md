### C++과 C# 에서 static 변수의 적재 시점

#### C++ static

> 프로그램 실행 직후  
> C++에서는 컴파일할 때 이미 모든 static 변수의 크기와 위치가 실행파일 내부의 데이터 영역에 고정됩니다. 따라서 메모리 공간 자체는 프로그램이 켜질 때 무조건 확보됩니다.

**메모리 확보**

⇒ 프로그램 로드 시

**초기화**

⇒ 상수 값은 로드 시 완료, 함수 호출이 필요한 값은 main전

---

#### C# static

> 해당 클래스가 최초로 참조될 때  
> C#은 C++처럼 함수 내부에 static 변수를 만들 수 없으며 모든 static 변수는 클래스 or 구조체의 소속임. C#의 런타임은 철저하게 필요할 때만 로드하는 지연 방식을 사용함

**클래스가 처음 사용될 때 적재 및 초기화**

Main 함수가 시작되었더라도 클래스를 아직 사용안했다면 그 클래스 내의 static 변수는 메모리 어디에도 존재 X

만일 이 클래스의 인스턴스를 처음으로 생성하거나 정적 필드나 정적 메서드를 처음 호출할 때 이때 메모리가 할당되고 초기화 됩니다.

### IPC

> 서로 다른 프로세스가 데이터를 주고 받거나 실행을 동기화하기 위한 통신 방법

프로세스는 각각 독립된 메모리 공간을 사용한다.  
따라서 a프로세스에서 b프로세스의 변수에 직접 접근하지 못함. 이때 사용하는 것이 IPC임

⇒ 프로세스 간 독립성을 유지하면서 협력 작업을 하기 위함

---

### IPC 기법

#### 1. 파이프

> 프로세스 사이에 데이터가 흐르는 통로를 만들어 데이터를 전달하는 방식

```text
Process A
    │
    ▼
  Pipe
    │
    ▼
Process B
```

- 데이터를 바이트 스트림 형태로 전달
- 일반적인 파이프는 단방향 통신을 기본으로 함

#### 2. 메세지 큐

> 프로세스 간 데이터를 메시지 단위로 전달하는 방식

```text
Process A
    │
    ▼
Message Queue
┌──────────┐
│ Message 1│
│ Message 2│
│ Message 3│
└──────────┘
    │
    ▼
Process B
```

- 메시지를 큐에 넣고 다른 프로세스가 가져감
- 송신자와 수신자가 반드시 동시에 실행될 필요는 없는 방식으로 구성
- 단위 데이터에 번호표를 붙여 커널의 큐에 넣고 빼는 방식
- 비동기 처리에 유리하며 여러 프로세스가 우선순위나 메시지 타입에 따라 골라서 데이터를 꺼내갈 수 있음

#### 3. 공유 메모리

> 여러 프로세스가 물리 메모리의 특정 구역을 두 프로세스의 가장 주소 공간에 동시에 연결함. 한쪽이 변수에 값을 쓰면 다른 쪽에서 즉시 보임.

- 데이터를 주고받을 때 반복적인 복사 비용을 줄일 수 있어 효율적임.
- 대용량 데이터를 공유하는 데 유리함.
- 여러 프로세스가 동시에 접근하면 경쟁 상태가 발생할 수 있음.
- 따라서 뮤텍스나 세마포어 등의 동기화 수단이 필요함
