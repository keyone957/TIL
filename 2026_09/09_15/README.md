### 2D 평면에 N개의 객체가 있고 플레이어의 위치에서 가장 가까운 객체를 반환하려면 어떤 방식과 자료구조를 사용해야함??

### 공간 분할 자료구조로 가까운 객체를 찾기

매번 N개 전체를 확인하는 대신 공간을 **여러 구역으로 나누고 현재 위치 주변 구역**의 객체만 검사하자.
    +----+----+----+
    |    | M1 |    |
    +----+----+----+
    | M2 | P  | M3 |
    +----+----+----+
    |    | M4 |    |
    +----+----+----+

가운데 플레이어가 있다면 전체 몬스터 n마리를 다 검사하는 것이 아니라 현재 셀 + 주변 8개 셀 안에 있는 몬스터들만 가져와 거리 비교를 함

#### 처리 과정

1. 월드를 일정 크기의 grid cell로 나눔
2. 각 객체가 어느 cell에 속하는지 저장
3. 플레이어가 속한 cell을 구함
4. 현재 cell과 주변 cell의 객체만 가져옴
5. 그 객체들과 거리 제곱을 비교해서 가장 가까운 객체를 찾는다.

#### Spatial Hash

Grid와 거의 같은 개념인데 모든 cell을 배열로 만들어두지 않고cell좌표 ⇒ 해당 cell의 객체 목록 형태로 Hash Table에 저장합니다.

ex)
    (2, 3) → Monster A, Monster B
    (2, 4) → Monster C
    (3, 3) → Monster D

따라서 넓은 월드에서 객체가 없는 빈 공간까지 메모리를 사용할 필요가 없다.

#### 쿼드 트리

공간을 항상 같은 크기로 나누는 대신 객체가 많은 영역을 재귀적으로 4등분함.

ex)
    전체 맵
     ├─ 좌상
     ├─ 우상
     ├─ 좌하
     └─ 우하
          ├─ 다시 4등분
          └─ ...

객체가 적은 지역 ⇒ 큰 영역 그대로 유지

객체가 몰려 있는 지역 ⇒ 더 작은 영역으로 계속 분할

* 장점
  객체 분포가 불균일한 넓은 맵에서 효율적

* 단점
  객체가 계속 움직이면 쿼드 트리에서 객체의 위치를 갱신해야 해서 동적인 객체가 매우 많을 경우 관리 비용도 고려해야 합니다.

### 정리

객체 수가 많다면 모든 객체를 매번 O(N)으로 탐색하기보다 Grid, Spatial Hash, Quadtree 같은 공간 분할 자료구조를 사용할 수 있습니다.예를 들어 Grid를 사용한다면 월드를 일정한 Cell로 나눈 뒤 각 객체를 자신이 위치한 Cell에 등록합니다. 이후 플레이어가 속한 Cell과 주변 Cell에 있는 객체만 가져와 거리 제곱을 비교하면 전체 객체를 검사하지 않고 가까운 객체를 찾을 수 있습니다.객체가 넓은 공간에 불규칙하게 분포한다면 Quadtree를 사용할 수도 있습니다.

### BFS에서 비교해야 할 노드의 수가 매우 많아진다면 최적화 방법?

### 양방향 BFS

시작점에서만 BFS를 하는 대신 목표 지점에서도 동시에 BFS를 시작해서 두 탐색이 중간에서 만나면 종료.각각 O(b^(d/2))만 탐색하면 되므로 단방향보다 훨씬 적은 노드를 탐색함.b ⇒ 분기수 / d ⇒ 목표까지 거리
